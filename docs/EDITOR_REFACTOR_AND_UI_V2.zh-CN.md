# VNDialogReborn 编辑器重构与 UI v2 方案（2026-09）

## 1. 结论

当前模组的主体能力已经完整：NeoForge 1.21.1 对话运行时、JSON 数据模型、网络同步、编辑器基础功能均已存在。真正的问题集中在编辑器：

- 入口 `VNDialogEditorScreen` 同时承担窗口布局、标签页、序列切换、快捷键、文件读写、导入、测试、历史和渲染；
- `PortraitListScreen`、`LogicPropertyPage`、`TextPropertyPage` 仍保留旧编辑器的“一个 Screen 包办一切”结构；
- 新加入的 `ui/core` retained UI 层目前只有数据结构，尚未成为真实事件与组件树；
- 脏状态以前按序列 ID 记录，重命名、重复 ID 和文件失败容易造成内存状态与磁盘状态不一致；
- 撤销历史以前是主屏唯一的 entries 快照，切换标签会丢失，属性修改不会进入同一历史。

本阶段不追求一次性重写全部 UI。先把稳定边界立住，再逐步替换旧 Screen：文档层、事件层、视图层分开，先保正确性，再做版式和视觉迁移。

## 2. 模组与编辑器现状审计

### 2.1 运行时层

- `model/`：`DialogSequence`、`DialogEntry`、`DialogOption` 是磁盘 JSON 的运行时模型。
- `DialogManager`：负责加载、同步、推进对话和测试模式。
- `network/`：负责编辑器打开、对话框同步、重载和服务端命令。
- `ui/`：正式对话播放界面 `DialogScreen` 与选项控件。
- `editor/`：编辑期专用代码，不应反向污染运行时模型。

结论：运行时模型可以继续保持兼容；编辑器元数据、历史、面板布局和验证信息不能直接塞进运行时 JSON。

### 2.2 编辑器债务量化

按本轮重构前源码统计，编辑器仍集中在少数巨型类：

| 类 | 行数级别 | 主要职责 |
| --- | ---: | --- |
| `VNDialogEditorScreen` | 1600+ | 标签、文件、布局、快捷键、渲染、保存、测试 |
| `PortraitListScreen` | 1100+ | 舞台、列表、属性、资源浏览、输入 |
| `LogicPropertyPage` | 800+ | 命令、条件、选项、物品、下拉框 |
| `DialogTreeWidget` | 700+ | 树构建、搜索、渲染、滚动、重命名 |
| `TextPropertyPage` | 600+ | 文本、翻译、颜色、格式 |

这五类不是“代码多”本身有问题，而是职责没有边界，导致任何 UI 调整都要触碰文件、模型和渲染三条链。

## 3. 本阶段已落地的重构

### 3.1 文档状态层

新增：

- `editor/document/EditorDocument`：每个打开序列一份独立状态；
- `editor/document/EditorDocumentStore`：统一路径、保存、重命名、删除的文件边界。

已迁移：

- 脏状态从“按字符串 ID 的集合”改为“按文档对象的状态”；
- 撤销历史从主屏全局栈改为每文档独立栈，切换标签不再清空；
- 保存使用临时文件 + 原子替换，并统一做安全 ID 与目录越界校验；
- 序列重命名先移动文件、成功后才改变内存 ID；目标冲突或移动失败不会产生半完成状态；
- 删除节点时保留空目标选项，不再因为目标为空而静默改变选项数组。

### 3.2 仍需继续迁移

- `VNDialogEditorScreen` 仍是主工作区宿主，但已经具备把文档状态抽离的条件；
- `EditorScreenState` 仍是全局可变单例，只适合作为过渡；后续应并入工作区 session；
- `ui/core` 和 `UiEventRouter` 尚未接管真实事件，不能声称“统一路由已完成”；
- 文件夹和资源路径仍有个别旧代码直接 `resolve`，需要继续收口到 store/service；
- 属性字段修改已有 dirty 通知，但尚未统一进入文档命令历史。

## 4. UI v2：创作优先的停靠工作台

### 4.1 顶层结构

```text
┌ 命令栏：新建 打开 保存 | 撤销 重做 | 搜索 验证 试玩             ┐
├ 标签栏：序列 1* | 序列 2 | +                                  ┤
├──────────────┬──────────────────────────────┬────────────────┤
│ 结构导航      │ 流程创作区                    │ 检查器          │
│ 搜索/筛选     │ 剧本卡片 + 分支              │ 身份/文本/表现  │
│ 节点/分组      │ 内联选项/目标/验证            │ 流程/条件/命令  │
├──────────────┴──────────────────────────────┴────────────────┤
│ 状态栏：验证错误 当前节点 保存状态 自动保存                   │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 四个工作视图

1. **流程视图（默认）**：写作、顺序调整、分支查看、内联选项编辑。
2. **画布视图（可选）**：只用于跨段跳转、环路和复杂拓扑，不再承担全部编辑。
3. **检查器**：所有长文本、命令、条件、资源选择都集中在此，不覆盖流程区。
4. **验证与试玩**：从当前节点或起点运行，显示当前路径、条件和失败原因。

### 4.3 响应式规则

- `width >= 1100`：三栏固定停靠；左侧 200~260，右侧 300~380，中央最小 360。
- `820 <= width < 1100`：左侧可折叠；检查器固定停靠，中央优先。
- `width < 820`：单栏模式；结构导航和检查器变成左右抽屉，不把中央压到不可读。
- 选中节点不改变面板宽度，不触发画布/列表视角跳动。
- 弹层、下拉框、输入框有唯一事件所有者；关闭弹层前不允许点击穿透。

### 4.4 组件协议

所有新组件统一遵循：

```text
measure -> layout -> render -> capture -> target -> bubble
```

基础组件至少包括：

- `UiPanel`、`UiButton`、`UiTextField`、`UiTextArea`；
- `UiSelect`、`UiList`、`UiTabs`、`UiModal`；
- `UiScrollView`、`UiSplitter`、`UiStatusBar`。

已有 `UiNode`、`UiEvent`、`UiEventRouter` 先作为协议骨架，不直接承载业务字段。旧 `AbstractWidget` 类通过适配器接入，避免一次性替换全部属性页。

### 4.5 视觉原则

- 保持炭黑、金属灰、荧光黄、青色、橙色的终末地式信息层级；
- 颜色只作为辅助，节点 ID、分支编号、验证文本必须可读；
- 面板标题、字段、状态和危险操作使用固定的语义色；
- 不使用大面积模糊、玻璃、阴影和无意义渐变；
- 每个视图只在鼠标所在容器消费滚动、键盘和拖拽事件。

## 5. 实施顺序与验收

### Phase A：已完成

文档状态、文件 store、原子保存、重命名事务、空目标选项语义。

验收：保存失败不误报成功；重命名失败不改内存；标签切换不丢历史；节点删除不静默丢选项。

### Phase B：下一步

拆分 `VNDialogEditorScreen` 的工作区宿主，接入真实 `UiEventRouter`，把 `PropertyPanel` 的鼠标/键盘转发改成统一 capture/target/bubble。

验收：下拉框、输入框、滚动条、快捷键无互相抢占；GUI scale 改变不产生残留控件。

### Phase C：大型 Screen 拆分

- `PortraitListScreen` → 舞台视图、资源列表、检查器、弹窗；
- `LogicPropertyPage` → 结构化表单、条件行、命令行、选择器；
- `TextPropertyPage` → 文本域、翻译区、格式工具栏；
- `DialogTreeWidget` → 树模型与渲染器分离。

验收：每个新页面只依赖文档命令、验证服务和主题协议，不直接写 JSON 文件。

### Phase D：工作流能力

搜索替换、书签、节点注释、脚本视图、试玩路径回溯、自动保存与恢复。

验收：50~200 节点序列的主要编辑不需要打开无限画布，验证错误可一键定位，试玩不污染正式数据。
