# VNDialogReborn 可视化编辑器重设计方案

## 0. 结论先行

当前编辑器的问题不是“颜色或按钮不够漂亮”，而是工作模型错误：把运行时的扁平节点数组直接包成树，再额外叠加一个无限画布。结果是：

- 编辑器同时暴露 `next`、数组隐式顺序和 `options.target` 三套流转语义；
- 画布只有节点摆放和连线，没有真正帮助作者写作、验证和试玩的工作流；
- 画布与属性面板抢占鼠标、滚轮、方向键和 Enter，导致交互冲突；
- 节点卡片信息过少，边没有标签，分支多时无法阅读；
- 保存、撤销、序列级属性、ID、布局状态没有统一的编辑事务；
- 编辑器测试实际依赖 `DialogManager`，但编辑器不能显示“当前路径、条件、命令和失败原因”。

目标不是继续堆功能，而是把编辑器改成四个明确工作区：

1. **流程视图**：默认工作区，用于顺序编排、分支查看和快速编辑；
2. **画布视图**：用于复杂关系、跨段跳转和局部拓扑分析，不再承担所有编辑任务；
3. **检查器**：稳定、可搜索、分组折叠的节点/选项编辑器；
4. **验证与试玩**：随时告诉作者哪里坏了，并从任意节点运行。

## 1. 外部资料提炼

本方案参考了以下公开项目和文档：

- [TaleNode](https://github.com/fognil/TaleNode)：节点图、检查器、最小地图、实时验证、试玩、查找替换、脚本视图、子图和项目级数据分离。
- [Dialogue Forge](https://github.com/nikatopu/dialogue-forge)：从任意入口试玩、自动布局、搜索、多选、复制子图、导入导出和移动端的底部检查器思路。
- [NarrativeNode](https://github.com/netzkontrast/NarrativeNode)：画布负责结构，右侧编辑器负责长文本；层级/章节导航和实体矩阵用于大规模内容定位。
- [NeoForge Screen 文档](https://docs.neoforged.net/docs/1.21.1/gui/screens/)：GUI 坐标必须随 GUI scale 正确布局；控件事件按 children 顺序分发；滚动、裁剪、焦点和 z-order 必须由容器统一管理。
- [Panels Not Screens](https://github.com/CappleApple/panelsnotscreens)：可停靠面板、面板 z-order、裁剪和“事件被面板消费后不再穿透”的输入模型。

这些项目的共同规律：

- 画布是导航和关系分析工具，不是表单；
- 长文本、命令、条件等复杂属性都在检查器中完成；
- 结构列表是画布的替代入口，不能因为有画布就取消；
- 搜索、验证、试玩、聚焦和撤销必须是一级能力；
- 运行时 JSON 与编辑器布局/注释/工作区状态应分离。

## 2. 当前仓库问题清单

### 2.1 交互与排版

涉及文件：

- `editor/gui/VNDialogEditorScreen.java`
- `editor/gui/widget/DialogCanvasWidget.java`
- `editor/gui/widget/DialogTreeWidget.java`
- `editor/gui/widget/PropertyPanel.java`

主要问题：

1. 顶部工具栏、标签栏、树、画布、属性面板都由一个 Screen 手工管理，布局没有统一 dock/constraint 系统。
2. 画布使用“左键拖节点、空白拖平移、中键拖平移、右键菜单、端口拖线、Ctrl 滚轮缩放”，但没有统一的工具状态栏；用户无法判断当前鼠标行为。
3. 画布右侧检查器展开后改变画布宽度，可能导致鼠标下节点瞬间改变位置；节点被选中时又会触发 `ensureVisible`，造成视角跳动。
4. 画布上的节点宽度只有 96 world px，摘要被截断，选项端口只有颜色和数字，没有选项文字；边多时信息密度不足。
5. 连线以采样贝塞尔曲线绘制，悬停命中也是采样近似；边交叉、同源多边、反向边和悬空边没有专门处理。
6. 树视图把图压成单棵树。汇合节点、循环、重复引用和隐式顺序在树中表现不准确。
7. 输入事件由主 Screen、画布、属性页分别处理，Ctrl、方向键、Enter、滚轮存在抢占；部分控件依赖手工转发。

### 2.2 数据与编辑状态

1. `SequencePropertiesScreen.saveAndClose()` 修改 title/description/effect/start，但主 Screen 没有 `markDirty`，可能关闭后丢失。
2. 加载、导入、新建没有统一的 ID 唯一性检查；dirty 集合按字符串 ID 记录，重复 ID 会互相污染。
3. 重命名先改内存后移动文件，目标冲突或移动失败时可能出现内存、文件和 dirty 状态不一致。
4. 编辑器多处强制 `setAllowClose(true)`，保存后可能改变原始运行时语义。
5. 画布布局只存在 `EditorScreenState`，关闭编辑器后丢失。
6. 结构修改进入历史，属性编辑没有进入同一事务模型；撤销行为不一致。
7. `DialogSequence.getRemainingEntries()` 没有 visited 集合，循环图可能无限遍历。
8. 删除节点会直接移除没有目标的选项，可能改变选项顺序和作者正在编辑的语义。
9. 文件路径普遍直接 `base.resolve(userInput)`，应统一做规范化、越界检查和扩展名限制。

## 3. 目标信息架构

### 3.1 顶层布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 项目/序列标签      保存状态  撤销/重做  验证  试玩  搜索  视图      │
├─────────────┬───────────────────────────────────────┬──────────────┤
│ 结构导航栏   │ 主工作区                               │ 检查器       │
│             │ 流程视图 / 画布视图 / 脚本视图         │ 节点属性     │
│ 入口         │                                       │ 选项属性     │
│ 节点列表     │                                       │ 资源预览     │
│ 搜索/筛选    │                                       │ 验证详情     │
├─────────────┴───────────────────────────────────────┴──────────────┤
│ 状态栏：错误数 / 警告数 / 当前节点 / 自动保存状态 / 试玩入口       │
└──────────────────────────────────────────────────────────────────────┘
```

默认尺寸策略：

- 左栏 220~280 px，可拖动，最小 180 px；
- 右栏 300~380 px，可拖动，最小 260 px；
- 中间工作区始终保留至少 360 px；
- 小于 900 px 的 GUI 宽度时进入“单栏模式”：检查器变为右侧抽屉，左栏变为可切换抽屉；
- 不再在选中节点时自动改变画布宽度。面板开关只改变 dock 布局，不改变相机中心。

### 3.2 顶栏分组

顶栏只保留高频动作，并使用图标 + tooltip：

- 文件：新建、打开、保存、另存为；
- 编辑：撤销、重做；
- 导航：聚焦起点、适应全部、查找；
- 质量：验证面板、错误/警告数量；
- 运行：从起点试玩、从当前节点试玩；
- 视图：流程、画布、脚本；
- 面板：结构栏、检查器、最小地图开关。

低频功能移动到菜单：导入、导出、删除文件、资源目录、语言文件、布局重置。

## 4. 三种主视图

### 4.1 流程视图：新的默认视图

流程视图不是当前树视图的简单美化，而是面向写作的垂直流程列表：

- 每行一个节点，显示：类型、ID、说话者、正文首行、选项数量、目标、错误标记；
- 普通线性节点以单列排列；
- 选择节点展开为分组行，选项显示在节点下面，目标用可点击引用；
- 汇合、循环和跨段跳转用明确的关系标记，而不是复制成树节点；
- 支持拖拽排序，但只有在“启用隐式顺序”时才改变数组顺序；
- 支持批量选择、批量删除、批量标签、批量替换；
- 支持“只看错误”“只看孤儿”“只看某说话者”“只看某资源”。

流程视图解决大部分日常编辑工作：写台词、改顺序、检查选项、跳转目标。画布不再被迫承担这些任务。

### 4.2 关系视图：由流程列表承担

当前版本移除无限画布界面，关系信息统一在流程列表和检查器中表达：

- 流程列表按运行时数组顺序展示节点、正文、选项和目标；
- 选项编号、目标编号、目标卡片边条使用同一稳定颜色；
- 点击目标行可以直接跳转并打开目标节点检查器；
- 悬空引用、循环、空文本和不可达节点由验证面板统一定位；
- 检查器中的逻辑页负责修改 `next`、选项目标和命令。

### 4.3 脚本视图

为长文本和翻译提供接近写作软件的视图：

- 左侧节点列表，右侧连续脚本；
- 显示说话者、正文、选项和命令；
- 支持全文搜索和查找替换；
- 支持导出为可读的 Markdown/纯文本（后续阶段）；
- 任何脚本行点击后都能定位到流程视图/画布节点。

## 5. 检查器重设计

检查器固定为右栏，不能被节点卡片覆盖。分组如下：

1. **身份**：节点 ID、类型、起点、结束标记；
2. **文本**：说话者、正文、翻译键、格式预览；
3. **表现**：立绘、位置、亮度、缩放、偏移、动画、背景；
4. **流程**：next、选项列表、目标选择器；
5. **条件与命令**：可见性命令、节点命令、选项命令；
6. **媒体**：音频、图片预览和资源存在性；
7. **调试**：该节点的上游、下游、可达性、循环、验证信息。

规则：

- 每组可折叠，折叠状态按序列保存；
- 字段修改立即写入事务系统，但输入框失焦时才提交昂贵的重建；
- 所有引用字段都使用可搜索的节点选择器，不让用户手输 ID；
- 选项使用可拖拽列表，目标、条件、命令均在同一行快速浏览；
- 删除选项不因目标为空而自动移除；空目标表示“点击后结束”或“待修复”，由验证器区分；
- 资源字段显示“存在 / 缺失 / 内置”状态；
- 预览使用固定尺寸和裁剪区域，不因原图尺寸改变布局。

## 6. 输入和事件路由

实现一个统一的 `EditorInputRouter`，所有 Screen 和 Widget 先向它请求捕获：

```text
Overlay/Modal > Popup > Inspector field > Active tool > Canvas/List > Screen shortcut
```

约束：

- 已展开弹窗时，点击、滚轮和键盘都不能穿透；
- 文本框聚焦时，方向键、Ctrl+C/V/Z 只属于文本框；
- 流程列表快捷键只在列表或编辑器拥有焦点时生效；
- 滚轮只由鼠标下的容器消费；
- 每次拖拽有唯一 capture owner，直到 mouseReleased；
- Esc 按优先级关闭弹窗、取消连线、退出工具、关闭检查器抽屉、最后才关闭编辑器；
- 不再由主 Screen 手工猜测 `getFocused() instanceof EditBox`。

推荐快捷键：

| 快捷键 | 行为 |
|---|---|
| `Ctrl+S` | 保存当前序列 |
| `Ctrl+Shift+S` | 另存为 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |
| `Ctrl+F` | 搜索节点、文本、资源 |
| `F` | 聚焦选择；无选择时适应全部 |
| `Home` | 聚焦起点 |
| `Space + 拖拽` | 平移画布 |
| `Ctrl+滚轮` | 以鼠标为中心缩放 |
| `Enter` | 打开检查器，不改变画布布局 |
| `Delete` | 删除选中对象，支持多选 |
| `Esc` | 按上述优先级取消/关闭 |

## 7. 数据模型与持久化

### 7.1 运行时数据与编辑器元数据分离

保持现有运行时 JSON 尽量兼容，新增编辑器元数据文件：

```text
config/vndialog_editor/
  dialog_json/<id>.json          # 运行时数据
  editor_meta/<id>.json          # 画布坐标、折叠状态、书签、注释、视角
  editor_sessions.json           # 打开的序列和活动视图
  lang/                          # 翻译缓存
  portraits/ backgrounds/ sounds/
```

`editor_meta` 示例：

```json
{
  "version": 1,
  "sequenceId": "test_dialog",
  "layout": {
    "start": {"x": 80, "y": 120}
  },
  "viewport": {"x": 0, "y": 0, "scale": 1.0},
  "collapsedGroups": [],
  "bookmarks": ["start"],
  "notes": {}
}
```

### 7.2 编辑事务

新增 `EditorDocument`：

- 包含 `DialogSequence`、唯一编辑实例 ID、dirty 状态、元数据、验证结果；
- 所有结构和属性修改都通过 `EditorCommand` 提交；
- 命令包含 before/after 快照或细粒度变更；
- 保存、撤销、重做、测试、关闭都使用同一文档状态；
- 序列 ID 变化是特殊事务：先验证、再移动文件、最后提交内存状态；失败时完整回滚。

### 7.3 ID 与文件安全

- 新建/导入/加载禁止重复编辑实例；
- ID 只允许 `[a-zA-Z0-9_./-]` 中的安全子集，禁止 `..`、路径分隔符和空白；
- 重命名检查内存重复和目标文件存在性；
- 所有文件都通过 `normalize()` 后确认仍位于对应 base directory；
- 保存采用临时文件 + 原子移动，避免游戏崩溃留下半个 JSON。

## 8. 验证器

新增独立的 `DialogValidator`，不依赖 UI，每次文档变更后增量运行：

- `ERROR_DUPLICATE_ID`
- `ERROR_DANGLING_NEXT`
- `ERROR_DANGLING_OPTION_TARGET`
- `ERROR_INVALID_START`
- `ERROR_EMPTY_ENTRIES`
- `ERROR_INVALID_RESOURCE_PATH`
- `WARNING_UNREACHABLE_NODE`
- `WARNING_IMPLICIT_ORDER`
- `WARNING_CYCLE`
- `WARNING_EMPTY_TEXT`
- `WARNING_OPTION_WITHOUT_TARGET`
- `WARNING_COMMAND_PARSE`

验证面板支持：

- 按错误/警告/节点筛选；
- 点击问题定位到节点和对应字段；
- 一键修复可安全修复的问题，如删除悬空 `next`、设置起点、补充空目标；
- 保存和试玩前显示未解决 ERROR，但允许用户明确选择继续测试。

## 9. 试玩闭环

当前编辑器测试只是把 JSON 交给真实 `DialogScreen`。保留这条路径，但增加编辑器调试层：

- 从起点或当前节点开始试玩；
- 显示当前节点 ID、进入路径和触发的命令；
- 条件命令失败时显示原因；
- 试玩结束后返回原视图、原选中节点和原相机；
- 试玩前自动保存临时快照，不改变正式文件；
- 提供“当前分支重置”和“跳到下一个选项”用于 QA。

## 10. 实施分期

### Phase 1：先修正确性（不改大 UI）

- 修复序列属性 dirty；
- 去掉强制覆盖 `allowClose`；
- 统一 ID 校验、重命名事务和安全路径；
- `DialogSequence` 遍历增加 visited；
- 删除选项不再静默移除；
- 属性修改纳入历史；
- 添加基础 `DialogValidator`。

验收：任何字段修改、撤销、重做、关闭、重命名都不丢数据；坏引用可定位。

### Phase 2：重做布局和事件路由

- 实现 dock 布局和统一输入路由；
- 保留导航树、流程视图和属性页，解决尺寸跳动、事件穿透和焦点冲突；
- 添加面板开关、最小宽度、单栏模式；
- 建立稳定的状态栏和验证入口。

验收：GUI scale 变化、窗口尺寸变化、打开下拉框、拖拽和文本编辑均无穿透或错位。

### Phase 3：流程视图

- 新增流程列表作为默认视图；
- 支持搜索、筛选、多选、引用跳转和选项快速编辑；
- 将当前树视图降级为兼容入口或移除。

验收：不打开画布即可完成 80% 的节点创建、文本编辑、选项编辑和顺序调整。

### Phase 4：流程编辑增强

- 流程卡片内联编辑选项文本与目标；
- 节点上下移动、快速复制、批量选择和定位；
- 目标颜色、验证徽标和引用跳转保持一致。

验收：50~200 节点的典型对话中，作者可以在流程视图完成主要编辑，不依赖无限画布。

### Phase 5：元数据、脚本视图和试玩 QA

- 脚本视图、全文查找替换、书签和注释；
- 调试试玩、路径记录和验证报告。

验收：作者可以在流程、画布、脚本、试玩之间往返而不丢上下文。

## 11. 不建议继续做的事情

- 不要继续增加颜色、阴影、圆角、渐变来掩盖信息架构问题；
- 不要把所有字段都塞进节点卡片；
- 不要重新引入没有明确编辑收益的无限画布；
- 不要用数组顺序隐式表达关键流程后再用虚线“猜测性”显示；
- 不要让 UI 直接修改模型字段而绕过事务、验证和 dirty 状态；
- 不要在画布中支持没有语义约束的任意连线；
- 不要把编辑器布局写入运行时 JSON。

## 13. 终末地风格视觉规范（2026-09）

本版编辑器视觉参考了《明日方舟：终末地》的功能模块界面，同时吸收 VS Code Explorer、Godot Inspector 的布局原则，以及 ModularUI 的面板树和动态布局思想、ModernUI 的确定性渲染思想：

- 基础层使用炭黑与金属灰，避免纯黑造成文字发虚；
- 主操作使用荧光黄，系统信息使用青色，分支/任务使用橙色，错误使用珊瑚红；
- 面板标题采用米白底、编号色块和细边线，内容区域保持深色，形成清晰层级；
- 状态色同时出现在来源选项、目标编号和目标卡片边条上，颜色只做辅助，文字仍保留完整 ID；
- 组件使用方角、短横线和少量斜纹，避免大面积阴影、玻璃模糊和无意义装饰；
- 三栏工作区按窗口宽度计算，导航与检查器设置上下限，中央流程保留最小可读宽度。

- [VS Code User Interface](https://code.visualstudio.com/docs/getstarted/userinterface)：Explorer、面板、标签和状态栏的空间分工；

- [ModularUI](https://github.com/CleanroomMC/ModularUI)：面板树、动态尺寸和主题化组件；
- [ModernUI](https://github.com/BloCamLimb/ModernUI)：确定性文本与布局渲染。
